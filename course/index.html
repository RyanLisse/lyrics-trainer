The scissors, in code

This is the whole cutting step, from src/lyrics-core.ts. It is a pure function: text goes in, a list comes out, nothing else is touched.

src/lyrics-core.ts 
/** Split raw text into trimmed, non-empty lines. Handles \n and \r\n. */
export function processLyricsText(text: string): string[] {
    return text
        .split(/\r?\n/)
        .map(line => line.trim())
        .filter(line => line.length > 0);
}
PLAIN ENGLISH

A note to humans: this works for files from Mac/Linux (\n) and from Windows (\r\n).

Define a tool called processLyricsText. It takes text and promises to hand back a list of strings.

Start with the raw text...

...cut it at every line break, with or without the Windows carriage return...

...shave the spaces off both ends of every piece...

...and keep only pieces that still have at least one character.

Done: the stack of cue cards goes back to whoever asked.

💡
Why the logic lives in its own file

Keeping DOM-free logic in lyrics-core.ts means tests can call it directly with a string. Tell an AI "put this in the pure core and unit-test it" and you get code that is easy to check.

02

Two Numbers Run the Show

The app's entire memory of "where am I" fits on a sticky label

The metaphor: a music stand with a clip and a metronome

A musician practising needs only two facts: which bar the clip is on and how fast the metronome ticks. Everything else can be worked out from the sheet music. The trainer's state is exactly that pair.

#

idx

Which line you are on, counting from 0. Line 1 on screen is idx 0.

⏱

delay

How many milliseconds auto-advance waits. 3000 means 3 seconds.

∑

Everything else

Counter text, progress %, button labels: all derived from idx and the lyrics list.

The shape of the state

An interface declares the shape, and a constant gives the starting values.

src/lyrics-core.ts 
export interface TrainerState {
    idx:   number;
    delay: number;   // milliseconds
}

export const DEFAULT_STATE: Readonly<TrainerState> = { idx: 0, delay: 3000 };
export const MIN_DELAY = 500;
export const MAX_DELAY = 10000;
PLAIN ENGLISH

Here is the shape every trainer state must have:

a line number...

...and a delay, measured in thousandths of a second.

That is the whole shape.

 

Start on the first line with a 3-second delay, and nobody may edit this default.

Auto-advance can never be faster than half a second...

...or slower than ten seconds.

Moving the clip: next and previous

Next and Previous do not behave symmetrically, and that is a deliberate choice. Read the two small functions and spot the difference.

src/lyrics-core.ts 
/** Index after "Next": wraps from the last line back to the first. */
export function nextIndex(idx: number, length: number): number {
    if (length <= 0) return 0;
    return idx >= length - 1 ? 0 : idx + 1;
}

/** Index after "Previous": stops at the first line. */
export function prevIndex(idx: number): number {
    return idx > 0 ? idx - 1 : 0;
}
PLAIN ENGLISH

Next loops around like a repeat sign in music.

Given the current line and how many lines there are...

...if there are no lines at all, just say 0.

On the last line? Go back to the top. Otherwise, one step forward.

 

 

Previous hits a wall instead of looping.

Given the current line...

...step back one, unless you are already at the top.

 

🔎
Small rule, visible effect

Because Next wraps, the Next button relabels itself "Restart" on the last line. That label comes from state too: the screen always tells the truth about what the next press will do.

The safety rail: clampIndex

Whatever number arrives (from a slider, a saved session, a bug), clampIndex squeezes it into the valid range before it becomes the state. Think of it as the end stops on a slide rule.

1
clampIndex(-3, 14) → 0

Below the first line? Pinned to the first line.

2
clampIndex(99, 14) → 13

Past the end? Pinned to the last line (the 14th, which is idx 13).

3
clampIndex(4.7, 14) → 4

Not a whole number? The fraction is chopped off.

State in, screen out

"The view is a function of the state" is the idea behind React, Vue and Svelte. This app does it by hand in 30 lines. Ask an AI to "update the state, then call render()" rather than poking individual elements, and bugs where the screen and data disagree disappear.

The slide, and when to skip it

Each new line slides in from the side you moved towards. Some people get motion sickness from animation, and their operating system can say so through a media query called prefers-reduced-motion.

src/script.ts 
/** Restart the slide/fade animation on the lyrics box (skipped for reduced motion). */
function animateLine(direction: Direction){
    const box = els.box;
    box.classList.remove('line-enter-forward', 'line-enter-backward');
    if (direction === 'none' || prefersReducedMotion()) return;
    void box.offsetWidth; // force reflow so the same animation can replay
    box.classList.add(`line-enter-${direction}`);
}
PLAIN ENGLISH

What this does, in one sentence.

Given a direction (forward, backward or none)...

...grab the lyric box.

Take off any slide that is still attached from last time.

If we did not really move, or the user asked for less motion, stop here: the text just appears.

Make the browser measure the box. This odd trick lets the same animation play twice in a row.

Attach the slide class; the CSS does the actual 220ms movement.

 

The CSS in public/style.css has a second, independent guard: under reduced motion the animation is set to none. Belt and braces.

The keyboard switchboard

From setupUI() in src/script.ts. An event listener on the whole page decides what each key means.

src/script.ts 
    document.addEventListener('keydown', e=>{
        // Let sliders handle their own arrow/Home/End keys (avoids double-stepping)
        if (isFormControl(e.target) || e.altKey || e.ctrlKey || e.metaKey) return;
        if(e.key==='ArrowLeft') back();
        else if(e.key==='ArrowRight') advance();
        else if(e.key===' '){ e.preventDefault(); toggleTimer(); }
        else if(e.key==='Home'){ e.preventDefault(); goTo(0); }
        else if(e.key==='End'){ e.preventDefault(); goTo(lyrics.length-1); }
    });
PLAIN ENGLISH

Whenever any key goes down anywhere on the page, run this:

(why the next line exists)

If a slider or text box has focus, or a shortcut key is held, ignore it. That key is not for us.

Left arrow: one line back.

Right arrow: one line forward.

Space: stop the page scrolling, then start or pause auto-advance.

Home: stop the page jumping to the top, then go to the first line.

End: same idea, last line.

End of the listener.

⚠
The double-step bug this fixed

Before the isFormControl check, pressing → while the seek slider had focus moved the slider one notch and ran advance(): two lines per press. preventDefault() is the browser's "I have got this, do not do your usual thing".

Swipes: measuring the finger

On a phone, a touch event records where the finger landed and where it lifted. The difference decides the direction.

src/script.ts 
function handleSwipe(){
    const distance = touchEndX - touchStartX;
    if (Math.abs(distance) < MIN_SWIPE_DISTANCE) return;

    if (distance > 0) {
        back();      // Swipe right - previous
    } else {
        advance();   // Swipe left - next
    }
}
PLAIN ENGLISH

When the finger lifts, decide what the gesture meant:

How far did it travel sideways? Positive means rightwards.

Less than 50 pixels either way? Probably a tap or a wobble; do nothing.

 

Moved right, like turning a page back...

...go to the previous line.

Otherwise it moved left...

...so go to the next line.

A Note for Tomorrow: localStorage

How the app remembers your line, your speed and your song across reloads

The metaphor: a note in your coat pocket

Leave a note in your coat pocket tonight ("stopped at line 7, speed 3s") and tomorrow's you picks up exactly there. localStorage is that pocket. It only holds text, so the state is written as JSON.

lyricsTrainerStateYour line and speed: {"idx":6,"delay":3000}
lyricsTrainerTheme"dark" or "light", if you picked one
lyricsPathWhich bundled file you had open, e.g. lyrics/casey_at_the_bat.txt
customLyricsThe full list of lines from a file you uploaded
lyricsSource"custom" or "playlist": where the current lyrics came from

Reading and writing the note

Two tiny functions in src/script.ts. Saving happens at the end of every render(), so the note is never more than one line out of date.

src/script.ts 
/* ---------- load / persist ---------- */
function loadState(): TrainerState {
    try { return parseState(localStorage.getItem(STORAGE_KEY)); }
    catch { return { ...DEFAULT_STATE }; }
}
function saveState(s: TrainerState){ localStorage.setItem(STORAGE_KEY, JSON.stringify(s)); }
PLAIN ENGLISH

This section is about remembering.

To read the note:

take the text stored under "lyricsTrainerState" and let parseState check it carefully...

...and if the browser refuses access entirely (some private modes do), just start fresh.

 

To write the note: turn the state into JSON text and store it under the same name.

Never trust a note you did not just write

The stored text could be from an old version, edited by hand in DevTools, or simply corrupt. parseState in src/lyrics-core.ts checks each field on its own and repairs what it can.

src/lyrics-core.ts 
    const { idx, delay } = parsed as Partial<Record<keyof TrainerState, unknown>>;
    return {
        idx: typeof idx === 'number' && Number.isFinite(idx) && idx >= 0
            ? Math.trunc(idx) : DEFAULT_STATE.idx,
        delay: typeof delay === 'number' && Number.isFinite(delay)
            ? Math.min(Math.max(delay, MIN_DELAY), MAX_DELAY) : DEFAULT_STATE.delay,
    };
PLAIN ENGLISH

Pull out the two fields, treating them as "unknown" until proven otherwise.

Build a fresh, clean state:

idx is kept only if it is a real, non-negative number...

...with any fraction chopped off. Otherwise use 0.

delay is kept only if it is a real number...

...and is squeezed between 0.5s and 10s. Otherwise use 3s.

Hand back the repaired state.

💡
Validate at the border

Anything that crosses into your app (saved data, uploads, network replies) is untrusted input. Checking it once at the border means the rest of the code can assume it is clean. When you ask an AI to persist data, also ask it to "validate on load".

Stocking the Hut: Offline with a Service Worker

How the app keeps working on a train with no signal

The metaphor: a mountain hut stocked before the storm

Walkers stock a mountain hut in good weather, so when the pass closes there is still food on the shelves. A service worker does that for the app: on first visit it fills a cache with every file the app needs.

1
Register

index.html asks the browser to run service-worker.js in the background.

2
Install: stock the shelves

Every file in the ASSETS list is downloaded into a cache named lyrics-trainer-v2.

3
Activate: clear out old stock

Caches from older versions (v1 and so on) are deleted.

4
Fetch: answer every request

From now on the worker decides: go to the network, or serve from the shelves?

The shopping list

The install step is all-or-nothing. If a single file on this list does not exist, the whole install fails and offline mode quietly never happens. That is exactly the bug the original exercise had.

public/service-worker.js 
// install: cache app shell
/** @param {ExtendableEvent} e */
self.addEventListener('install', (e) => {
    e.waitUntil(
        caches.open(CACHE).then((c) => c.addAll(ASSETS))
    );
});
PLAIN ENGLISH

This part runs once, when a new version of the worker is installed.

(a type hint for editors)

When the browser says "you are being installed"...

...ask it to wait until we are finished...

...open the cache for this version and download every file on the ASSETS list into it.

If any single download fails, the install fails.

 

Fresh when possible, stored when not

Lyrics files change, so for them the worker tries the network first and keeps a copy. The app shell (HTML, CSS, JS) rarely changes, so it comes straight from the shelves. This mix is called a caching strategy.

public/service-worker.js 
            if (isFreshContent(url)) {
                try {
                    const net = await fetch(req);
                    if (net.ok) {
                        const cache = await caches.open(CACHE);
                        // Store without the ?v= cache-buster so offline lookups match
                        await cache.put(url.origin + url.pathname, net.clone());
                    }
                    return net;
                } catch { /* offline: fall through to cache */ }
            }
            // The app adds ?v=<timestamp> to lyrics requests, so ignore the query string
            const cached = await caches.match(req, { ignoreSearch: true });
            return cached || fetch(req);
PLAIN ENGLISH

Is this a lyrics file or the playlist? Then:

try the internet first...

...and wait for the real file.

If it arrived fine...

...open the shelves...

(why the next line strips the address)

...and store a copy under the plain address, without the timestamp.

 

Give the page the fresh file.

No signal? Do not panic; carry on to the shelves below.

 

(why the next line ignores the ?v= part)

Look for a stored copy, ignoring the ?v=... part (remember the cache-buster from module 1).

Found one? Serve it. If not, try the network as a last resort.
