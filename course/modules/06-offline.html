Stocking the Hut: Offline with a Service Worker

How the app keeps working on a train with no signal

The metaphor: a mountain hut stocked before the storm

Walkers stock a mountain hut in good weather, so when the pass closes there is still food on the shelves. A service worker does that for the app: on first visit it fills a cache with every file the app needs.

1
Register

index.html asks the browser to run service-worker.js in the background.

2
Install: stock the shelves

Every file in the ASSETS list is downloaded into a cache named lyrics-trainer-v2.

3
Activate: clear out old stock

Caches from older versions (v1 and so on) are deleted.

4
Fetch: answer every request

From now on the worker decides: go to the network, or serve from the shelves?

The shopping list

The install step is all-or-nothing. If a single file on this list does not exist, the whole install fails and offline mode quietly never happens. That is exactly the bug the original exercise had.

public/service-worker.js 
// install: cache app shell
/** @param {ExtendableEvent} e */
self.addEventListener('install', (e) => {
    e.waitUntil(
        caches.open(CACHE).then((c) => c.addAll(ASSETS))
    );
});
PLAIN ENGLISH

This part runs once, when a new version of the worker is installed.

(a type hint for editors)

When the browser says "you are being installed"...

...ask it to wait until we are finished...

...open the cache for this version and download every file on the ASSETS list into it.

If any single download fails, the install fails.

 

Fresh when possible, stored when not

Lyrics files change, so for them the worker tries the network first and keeps a copy. The app shell (HTML, CSS, JS) rarely changes, so it comes straight from the shelves. This mix is called a caching strategy.

public/service-worker.js 
            if (isFreshContent(url)) {
                try {
                    const net = await fetch(req);
                    if (net.ok) {
                        const cache = await caches.open(CACHE);
                        // Store without the ?v= cache-buster so offline lookups match
                        await cache.put(url.origin + url.pathname, net.clone());
                    }
                    return net;
                } catch { /* offline: fall through to cache */ }
            }
            // The app adds ?v=<timestamp> to lyrics requests, so ignore the query string
            const cached = await caches.match(req, { ignoreSearch: true });
            return cached || fetch(req);
